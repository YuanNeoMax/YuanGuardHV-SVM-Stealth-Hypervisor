### P1-3 的进展（9.582 → 9.584）

先解决「能不能看」，再谈「看到什么」：

| 步骤 | 状态 |
|---|---|
| 同步守卫的计数器可读 | ✅ `sync-stats`（8 个计数器，含 `hits`）|
| 真 guest 下开 sync 稳定 | ✅ 3900+ 轮，`sys-health` 干净 |
| 让 `hits` 从 0 变非零 | ✅ **9.584 实测**：`set-target` → `protect-page` → `start` → `wpm-write` → `hits` 0→1 |
| 目标自写是否被回滚 | ✅ **9.584 实测**：10/10 存活，`hits` 不变 |

**`hits` 就是 P1-3 的全部故事，而它同时也是那个歧义本身**：
轮询只看到「页变了」，看不到「谁改的」——目标恢复自己的写、
和外部写入被挡住，加的是同一个计数器。现在这条限制**可测量**了，
但还没被测。

**9.583 的教训（错误码名字写错，代价是整轮排查方向错）**：

```
当时记录  0x490 ERROR_NOT_READY  [HIST]  -> 暗示「时机不对」，于是去试 config sync 0、换 mmf 页
实际      0x490 = 1168 = ERROR_NOT_FOUND
          RtlNtStatusToDosError 实测：只有 STATUS_NOT_FOUND (0xC0000225) 映射到 1168
          该状态在 add_page_for_pid 上唯一来源是 protect.c:1099「按 pid 查不到槽」
```

**错误码不是标签，它是从某一行 `return` 返回的。记下它之前先翻译回那一行。**

**9.584 实测记录**：

```
# P1-3b 根因确认
protect-page 3172 0x26824AB0000           -> 0x490 ERROR_NOT_FOUND
set-target 3172
protect-page 3172 0x26824AB0000           -> OK

# P1-3c 目标自写 vs 外来写
# 目标进程 selfwrite_hold.exe 自己写自己 armed 的页（10 次，间隔 200ms）
#   10/10 SURVIVED —— hits 不变（仍为 1）
# 外来进程 wpm-write 写同一页
#   1/1 ROLLED BACK —— hits 0→1，readback 为写入前的值

# 结论：守卫实际能区分来源，但代码不检查写入者 CR3
# 可能机制：COW（目标写触发 copy-on-write，守卫读原始页无差异）
#           或缓存一致性（MmCopyMemory 读物理页 vs 用户态写入缓存）
```

### P2-3 的最终结论（9.579 → 9.580 → 9.581）

判据补完了，结论仍然是不做。三段：

| 轮次 | 做了什么 | 结果 |
|---|---|---|
| 9.579 | 发现判据只成立一半 | `npt-remap` 会覆盖 DECOY，不能当刷 TLB 用 |
| **9.580** | 新增 `npt-raw <pa> f`：只刷 TLB、不改映射 | ✅ flush 后 DECOY 完好，A 位确实被清 |
| **9.581** | 新增 `sys-guard consistent`：比对 `hidden` 与 NPT 实际状态 | ✅ 四场景全对（含 2MB 大页误报修复）|

**现在「藏页之后有没有人读」这个问题可以回答了。**
但答案是：**那 54 页不该藏** —— 9.535 已经证明页上是驱动自己的
`g_npt` / `g_watchdog_stop` / `g_os_guest_stop_requested` 等 25 个控制流变量，
DECOY 会让驱动自己读到零。

判据的价值不在于让这件事变得可做，而在于让「不做」这个结论**可验证**而不是靠推测。

### P2-3 的实测结果（9.579）

**没有做全藏，因为前置判据只证明了一半。** 这一轮的价值是把"不知道"变成"知道缺什么"：

| 判据要素 | 结果 |
|---|---|
| 2MB 页让 54 个读数退化成 1 个恒等式 | 已解决（`npt-remap <gpa> <gpa>` 拆页）|
| 藏页后**没人读**，A 保持 False | ✅ 成立（20 秒 + 真实负载，A 始终 False）|
| 藏页后**有人读**，A 置位 | ❌ **未证** —— 需要一个不改映射的刷 TLB 手段 |
| `hidden` 计数与实际状态一致 | ❌ **不一致**（remap 后矛盾，且无检测）|

**硬阻塞是第三行**：`npt-remap` 被当成刷 TLB 用，但它**会把 DECOY 覆盖掉**
（`prev=0x0 → spa=真实页`，A 立刻变 True）。所以"有人读"这一半测不了。

**在它被补上之前，藏 54 页的成败仍然只能靠"跑一天没蓝屏"** ——
而那正是台账明确拒绝接受的判据。

## 四、判据纪律（这一节比清单本身重要）

盘点时发现的问题，几乎都是**判据失效**而非代码失效：

| 实例 | 判据怎么骗人的 |
|---|---|
| `invmrun=0x6` 被读成"停止信号太弱" | 它其实是"六个核的栈已不存在" |
| `early-returns=0` 被打印成"缺陷" | 桩模式下这是**正确读数** |
| `npt-view` 只认 `present=0` | 把 DECOY 的**成功隐藏**报成"没隐藏" |
| `mem-pte` 报 6/8 | 时序假象，不是缺陷 |
| 9.511 的"47 页从未被触及" | 观测窗口太短，**不是关于全部时间的断言** |
| 索引行数写 18 行 | 那条记录**根本没有正文** |
| 桩模式 11.6× 被当成全核代价 | 那是**桩自己空转**的开销 |

**所以每一条待办在开工前先回答两个问题**：

1. **我的判据能观察到这个事件吗？**（9.466 那条）
2. **如果这次读数变了，是代码变了还是判据变了？**

答不上来就先建观测，不要先改代码。
