## 三、必须知道的硬边界（不是待办，是物理事实）

### 3.1 CPU 100% 在本机无法消除

不是没优化好，是**硬件不给 C-state**：

```
powercfg /availablesleepstates
    此系统上没有以下睡眠状态:
        待机 (S1)  系统固件不支持此待机状态
        待机 (S2)  系统固件不支持此待机状态
```

没有 C-state 可进，`hlt` 执行后**立即返回**，它停不住核。
三条路都验过：

| 手段 | 削减 VMEXIT | 降低 CPU |
|---|---|---|
| 纯 `vmmcall` 重复 | 基准 | ✗ |
| 仅 `hlt` | **739 倍** | ✗（无 C-state）|
| `hlt` + `pause 1000000`（当前）| **19,200 倍** | ✗ |

**要真正降下来只有两条**：① 不做常驻虚拟化（架构改动，NPT 保护会变成窗口式）；
② 换一台有 C-state 的机器 —— **桩已经是 `hlt + pause` 形态，到那时无需改代码**。

### 3.2 `.rdata` 和 `.text` 永远不能藏

- `.text` 是取指页，`present=0` 会停掉我们自己的 fetch，且没有 ALLOW loop。
- `.rdata` **含 IAT**（RVA `0x28000`，第一页）。藏它 = 藏掉自己的导入表，
  之后 `call [IAT slot]` 读 0 跳到地址 0。**实测崩溃 `0x3B C0000005, rip=0`，
  而那指令本身完全正确。**
- 一个我们 **CALL THROUGH** 的页不能藏，和「一个我们执行它的页不能藏」是同一条原则。

### 3.3 `.data` 未试（54 页 · 按段跨度算（0x2F000..0x64693；虚表本身只有 9 页），风险最高）

含活状态。**建议先做「PA → 所属段」查询再动它**，否则藏错子区间会把自己弄坏。

## 四、这一轮的六条方法论（比任何单个修复都值钱）

每一条都对应我这次犯的一个错。

### 一、判据的局限 ≠ 被测对象的结论

`npt-view` 只认 `present=0`，于是把 DECOY 模式的**成功隐藏**报成「没隐藏」，
我据此写了「guard 表登记成功，NPT 条目没真正落地」——**那句结论是错的**。

同形态在 9.440 已犯过三次。**写结论前问一句「我的判据能观察到这个事件吗」。**

### 二、参数怎么调读数都不变时，先确认它有没有被执行

9.463 写「`pause 100000` 没效果」，9.464 又写「`hlt` 没效果」——
两次都在解释「为什么这个指令不起作用」，而事实是**这些指令根本没走到**。

### 三、被判为「无效」的手段，可能在错误的前提下被否决了

9.464 判 `hlt` 无效时，`hlt` 一次都没执行过。RIP 修好后重测：**739 倍**改善。

**规则：结论的依据若是「我观察到 X 没效果」，而 X 所在执行流后来被改过，必须重测。**

### 四、检查器自己也需要被检查

`exit_rip_contract.ps1` 三版都假失败过：

| 版本 | 假失败 |
|---|---|
| 把「下一个 case」当 body 结尾 | 25 个 |
| 只查 body 字面量 | `VMRUN` |
| 窗口差 17 行 | `SvHandleMsrAccess` |

**一个把好树报成坏的检查器比没有更糟**——它会训练人忽略它。

### 五、采样硬件持续更新的字段时，单次读数不是状态

`VIntr` 在 `0x0`/`0xE` 间摆动。单采一次就会把 `0xE` 误判成泄漏。

### 六、测量必须把时间基准一起记下来

用两次读数算速率却假定间隔 10 秒（实际 30–55 秒），报出过
「降 183 倍」和「CPU 0%」两个假结论。

**测 CPU：`Get-Counter '\Processor(_Total)\% Processor Time'` 采三次，基线 29%。**

## 六、操作纪律

- **改变机器状态的命令必须先得到用户明确确认**：`sc create/start/stop/delete`、
  驱动加载/卸载、压测、重启、启动链修改、**GitHub 推送**。
- **只读操作可直接执行**：源码阅读、`dumpbin`、`kd` 分析 dump、日志读取。
- **构建和蓝屏取证不需要确认**。
- 蓝屏后：**自动取证 → 定位 → 修复 → 重跑**，不中断问人。
- 优先级：**重启类最后、压测最后、小爆炸半径优先**。
- 改动一律记进 `YUANMOD_HANDOFF_CURRENT.md` 的 9.3xx/9.4xx 编号。

## 七、踩过的坑（会浪费你时间的那几个）

### 7.1 `yghv_ctl.ps1` 每条命令耗时 25–60 秒

不是挂死。这个 build 下 12 个核在 guest 里跑，每个 IOCTL 要排队。
**超时设 ≥ 300 秒**；把 120 秒的超时当成 hang 是浪费一轮。

### 7.2 别用 `[IO.File]::ReadAllText/WriteAllText` 反复整文件替换源码

这一轮把 `control_device.c` 和 `yghv_ctl.ps1` **写成了二进制**，
`read` 报 `binary file`、git 显示 `Bin 203860 -> 213377`。
用 `git checkout` 恢复后重建。**改源码用 `edit` 这类原子替换。**

### 7.3 pwsh 的 `cd` 不持久

有一次写到了 `D:\yuanguard\` 根目录（留下一个 0 字节野文件）。
**用绝对路径。**

### 7.4 `yghv_stealth_check.ps1` 必须传 `-ServiceName yghvpa`

不传的话查的是 `yuanguard`，那个服务不存在，于是**所有项都报 `CLEAN`**。

### 7.5 `npt-view` 的 `frame` 字段在大页条目上不是该页的帧

大页时它是 2MB 基址。判据必须先排除 `large=1`，再判 UNMAP/DECOY。

### 7.6 `exit-mask` 的"间隔"不能假定

命令自身耗时几十秒。**算速率必须打印实际墙钟间隔。**
